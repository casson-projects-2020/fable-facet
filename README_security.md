# Security Considerations and Code Analysis
This is a tool for developers, so we consider that you can analyse the code in this repo to see that our claims about security are true.

However, to help in this task, here are the main security concerns and the code analysis related to them.

## 1 - Gemini API Key never crosses your GCP account boundary
We ask you to paste an API key created for Gemini. The interface that you will see when we request that can be found in this repo at /templates/index.html. 

The setup interface is served via Google Cloud Shell Web Preview, running within your private GCP sandbox. It utilizes a Python Flask server on the same temporary VM provisioned by Google for your account. You can audit the server logic in /tutorial.py.

The API key is passed via JavaScript to the Flask server. You can see that on index.html:

<pre><code>
                const response = await fetch( './validate_key', 
                {
                    method: 'POST',
                    headers: { 'Content-Type': 'application/json' },
                    body: JSON.stringify({ key: elem( "gemini_key" ).textContent })
                });
</code></pre>

The python code in tutorial.py will validate the key:

<pre><code>
    try:
        client = genai.Client( api_key = key )
        models = client.models.list()

        env[ "GEMINI_KEY" ] = key

        return "ok", 200

    except Exception as e:
        return "Invalid key", 401
</code></pre>

Notice that the key, if valid, is set as an environment variable. In this way it can be used by Terraform to create
a cloud function v2 in your GCP account. Apart from the bucket with Terraform data (and the source code for the function,
that you can see in this repo in /function_code/main.py), this is the only resource created. You can
see the API key being used by Terraform in /yfc_install.sh:

<pre><code>
terraform apply -auto-approve -var="project_id=${PROJECT_ID}" -var="region=${REGION}" -var="infra_bucket=${BUCKET_NAME}" \
    -var="token=${TOKEN}" -var="api_key=${GEMINI_KEY}"
</code></pre>

And finally you can see how Terraform uses the API Key in main.tf:

<pre><code>
variable "api_key" {
  type      = string
  sensitive = true
}
...
resource "google_cloudfunctions2_function" "function" {
  name     = local.cf_name
  location = var.region
...
    service_config {
...
      environment_variables = {
      GEMINI_KEY = var.api_key
    }
</code></pre>

You will find no other uses for the API key (except inside the Cloud Function), so the key is only used inside your GCP account.

For security compliance, Fable Facet requires the use of Personal GCP Projects. Using a GCP account linked to a corporate Organization,
or shared with others, is prohibited, as users with elevated permissions (such as Organization Admins) could potentially extract the API
Key from your environment variables, violating the private nature of the key - and that may configure a Google's Terms of Use violation.

## 2 - While they cannot be for personal or consumer use, your GCP resources are never shared
Google's policies for Gemini API keys prohibits personal or consumer use - you as a developer have to use them to create a software. 
For personal, general use, you should visit the official free Gemini URL provided by Google: gemini.google.com. 

So you are joining a distributed software (Your-Fable-Cloud) using the Bring Your Own Infrastructure model. The service is designed 
to create and publish texts, and that cannot be changed by you - you should use the software as it is designed to be used, not for any
personal use other than that. As you join the network, you agree with this terms and all others applicable (please refer to the site).

While you can change the code that is installed on your own GCP account, if it is changed in a way that violates the purpose of the 
service, Google may charge, suspend or cancel your account, and Fable Facet also reserves the right to suspend or remove you from the
site and the service even if Google have not yet taken action. The community, and what can be seen on the site, is controlled by the
central API and is not affected by the external code of each user.

Modifications that don't violate the purpose of use of the software (adding your own prompts to Gemini, for instance) are allowed, but 
you should be the only one affected by them. Any modification is at your own risk - the security system may prevent you from using the
site depending on the modifications, for instance. Please submit to us modifications that you intend to do for validation.

Apart from that, your resources are never shared. It means that only the requests generated by you, or that you need to be part of
the service, are processed by your infrastructure. Your GCP account operates as a single-tenant environment. Fable Facet does not multiplex or share your GCP resources with other users.

Fable Facet central API or site may only send requests to your cloud function if it is as a part of a register - adding your data 
to our central database, for instance, and never to use Gemini. 

You will be using your Gemini API key to create and publishing texts. You can create them using your own notes as an author, or using
notes created by others, but any text created by you will be processed by your GCP account. No other user, nor Fable Facet site or
API will send requests to your Gemini API key.

You are responsible to protect your own passwords - the one that give access to your GCP account, and the one that give access to your
email account.

Some cases, as for instance moderation to avoid offensive content, is one example of something that, 
if you remove from your code, will not be seen only by you, can leak into the Fable Facet community, and will cause your suspension 
or cancellation of service.

## 3 - If you want to delete your account
Since the resources are in your own GCP account, if you want to leave Fable Facet network, you can delete the cloud function and the 
bucket at anytime. You can also use

<pre><code>
terraform destroy
</code></pre>

On the console (in this case, don't delete the bucket because Terraform needs the data saved there to remove the resources)

There is also a "Delete my Account" option on Fable Facet site that removes any data collected from you from our database.

However in some cases you don't have Intellectual Property (IP) Rights over published texts. While you can work on texts and retain 
full rights over them, texts created with other users' notes, published in the "free tier" category, or or those containing significant unedited AI-generated content are considered as Public Domain and will be removed at Fable Facet discretion. Upon deletion, your Author's page will be removed, but these specific texts may remain on the platform under a generic or fictional pseudonym.

Additionally your texts remain stored locally in your device. While the browser will remove them if you use "Delete my Account", 
you are responsible to delete the texts if you had ever used the "Export" option.

The account deletion process is **irreversible**. To comply with privacy standards, Fable Facet will erase all links between your
identity and content generated by you but without Intellectual Property. Should you choose to rejoin the community later — even 
using the same email address — your previous works will not be restored or re-associated with your new profile. Any content retained 
by the platform will remain anonymized or under a pseudonym, as the original association has been permanently purged.
